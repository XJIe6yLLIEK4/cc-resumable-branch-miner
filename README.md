# Resumable Branch & Quarry Miner

Добывающая черепаха для **CC:Tweaked 1.108+**, в том числе Minecraft 1.20.1.
Сохраняет задание, копает главный тоннель с боковыми ветками или квадратный карьер
вниз до бедрока и разгружает добычу у **неизменной исходной базы**.

**`resume` продолжает старое задание. Место остановки никогда не становится новой базой.**
Каждая черепаха хранит свои данные в собственной файловой системе. Внешние Lua
библиотеки, управляющий компьютер и новые моды не нужны. GPS для автоматической
проверки неоднозначных остановок можно построить средствами самого CC:Tweaked.

## Что умеет

- Главный тоннель шириной 1 и высотой 2, боковые ветки слева и справа.
- Карьер заданного радиуса: сплошные квадратные слои, проход змейкой с разворотом
  маршрута на следующем слое. Неровный бедрок обходится через уже очищенный слой.
- На выходе из ветки сканирует стены и пол, возвращается на уровне выше и
  сканирует стены и потолок. Базовый путь боковой ветки длиной L — **2L + 2**
  перемещения, не считая обхода жил.
- Добывает руды из модов по тегам `forge:ores` / `c:ores` и именам `*_ore`;
  распознаёт древние обломки. Обход жил ограничен радиусом и числом блоков.
- Сохраняет каждый шаг и поворот, текущую ветку или слой и клетку карьера,
  обход жилы и этап обслуживания.
- При заполнении возвращается к старой базе, разгружается и возвращается к
  сохранённой точке работы. Запас на обратный путь проверяет заранее.
- При пустом баке, заполненном сундуке или препятствии ждёт и повторяет попытку.
- После загрузки чанка или перезапуска компьютера продолжает сохранённое задание.
- Конечная шахта или непрерывная добыча с количеством пар веток `0`.

## Установка

На свежей добывающей черепахе с киркой:

```text
wget run https://raw.githubusercontent.com/XJIe6yLLIEK4/cc-resumable-branch-miner/main/install.lua
```

Установщик сначала скачивает и проверяет синтаксис файлов. Он не перезаписывает
существующие `branchminer.lua` и `startup.lua`. Программа не переносит состояние
других добывающих скриптов.

Для ручной установки скопируйте `branchminer.lua` и `startup.lua` в корень
файловой системы черепахи. Если у неё уже есть автозапуск, сохраните его логику
и добавьте вызов `shell.run("/branchminer.lua", "boot")` при загрузке компьютера.
Служебную команду `boot` не запускайте вместо `resume` в уже работающем компьютере.

Для обновления существующей установки до **1.1.0** сначала остановите работника
командой `branchminer pause` из второго окна и дождитесь выхода программы, либо
удержите Ctrl+T. Затем выполните:

```text
wget run https://raw.githubusercontent.com/XJIe6yLLIEK4/cc-resumable-branch-miner/main/install.lua --update
```

Обновление проверяет синтаксис скачанного файла, сохраняет предыдущую версию
программы и оставляет `startup.lua`, данные задания и исходную базу на месте.
Существующая шахта версии 1.0 продолжится через `branchminer resume`.
Обновление программы само по себе не меняет её режим и не запускает новый карьер.

## Расстановка базы

1. Поставьте черепаху в начале **новой** шахты и направьте вдоль главного тоннеля.
2. Поставьте **сундук добычи непосредственно сзади**, на высоте черепахи.
3. Поставьте **сундук топлива непосредственно под черепахой**. В нём должны быть
   уголь, древесный уголь или угольные блоки. Начальное топливо можно дать и в
   инвентарь самой черепахи.
4. Оставьте путь к этой базе свободным. Для двух черепах используйте две отдельные
   базы и непересекающиеся области шахт.
5. Обеспечьте активную загрузку всей области, обратного пути и сундуков.

Точка установки становится относительным `(0,0,0)` только при создании нового
задания командами `new` или `quarry`.
Относительный X направлен вправо от стартового направления, Z — вперёд, Y — вверх.
Черепаху с активным заданием нельзя ломать, переносить или поворачивать вручную.

## Команды

```text
branchminer new 30 20 3
branchminer status
branchminer pause
branchminer resume
```

Аргументы `new`: **длина боковой ветки**, **число пар веток**, **расстояние между ними**.
Пример выше создаёт 20 пар по 30 блоков с шагом 3; главный тоннель продвинется на
60 блоков. `new` и `quarry` откажутся заменить незавершённое задание.

Для непрерывной добычи:

```text
branchminer new 30 0 3
```

Запущенная программа занимает терминал. На улучшенной черепахе команды `pause`
и `status` можно выполнять из второго окна shell. `pause` останавливает на
безопасной границе действия. Можно также удержать **Ctrl+T**, а затем выполнить
`branchminer resume`: незавершённое физическое действие останется в журнале.

Команда `cancel` явно завершает сохранённое задание. Она не возвращает черепаху
домой и не восстанавливает выкопанные блоки. После отмены можно разместить её
на новом старте и выполнить `new`. Статус и база старого задания сохраняются
до явного создания нового.

## Карьер вниз до бедрока

```text
branchminer quarry 5
```

**Радиус 5 означает квадрат 11×11**: ширина и длина равны `2 × радиус + 1`.
Допустимый радиус — целое число от 0 до 32; радиус 0 даёт колонну 1×1.
Карьер расположен **впереди базы**, чтобы сохранить сундук топлива под ней и
сундук добычи позади неё. Стартовая черепаха находится за серединой ближней стороны.
В относительных координатах область: **X от −r до r, Z от 1 до 2r+1**.
Для радиуса 5 центр карьера — `(0,0,6)` относительно базы.

Первый слой находится на высоте стартовой черепахи, остальные — ниже него.
Черепаха проходит слой змейкой, опускается у его конца и проходит следующий слой
в обратном порядке. Верхние слои повторно не выкапывает. Добыча ограничена
выбранным квадратом: отдельный обход рудных жил и заделка пола в этом режиме
отключены. По умолчанию сохраняется вся порода; `--discard-common` необязателен.

При встрече с бедроком запоминает завершённую колонну и продолжает остальные,
обходя препятствия через последний полностью очищенный слой. Завершает работу,
когда все колонны дошли до бедрока, либо достигнут нижний предел высоты мира.
Другие защищённые блоки, например сундук или чужая черепаха, вызывают ожидание;
они не считаются дном карьера. Стартовый слой должен находиться выше бедрока.

При заполнении или нехватке топлива возвращается к **той же исходной базе**,
после обслуживания — к сохранённой точке работы. Если первый слой ещё не окончен,
путь к сундуку проходит по уже выкопанной части змейки; в глубине использует
очищенный слой и входную колонну. Сохраняются слой, клетка, неровности бедрока
и этап обслуживания. Команды `pause`, `resume`, `status`, `recover` и автозапуск
работают так же, как у тоннелей.

Пример с GPS и границами загруженного участка:

```text
branchminer quarry 5 --gps --heading north --bounds -5,5,0,11
```

Карьер создаётся как **новое** задание. Завершите старую шахту либо отмените её
через `cancel` и сами верните черепаху к базе перед запуском `quarry`.
Чтобы продолжить уже начатый карьер, используйте **`branchminer resume`**.

## Работа без игроков

**Программа не загружает чанки сама.** Выход игрока не мешает добыче только пока
чанки черепахи и всего её пути остаются активно загруженными. Подойдут имеющиеся
загрузчики TechReborn; их область должна включать обе стороны тоннеля и запас
на обход жил, либо весь квадрат карьера вместе с базой. При выгрузке черепаха физически не работает; после загрузки
`startup.lua` возобновит сохранённое задание.

Для долгой непрерывной шахты потребуется расширять покрытие загрузчиками. Наличие
игрока где-то на сервере, дальность прорисовки и загрузчик только возле сундука
не заменяют загрузку всей шахты. Добыча также требует топлива и свободного места
в сундуке. Пауза, явно сделанная пользователем, после перезапуска остаётся паузой;
завершённое или отменённое задание не запускается заново.

Можно задать безопасные границы загрузки **относительно старта**:

```text
branchminer new 30 20 3 --bounds -40,40,0,70
```

За эти границы рабочие перемещения и обход жил не выходят. В исходном сундуке
должно быть достаточно свободного места; область загрузки должна также включать
сам сундук позади точки `(0,0,0)`.

## GPS и остановка посреди движения

Для наиболее надёжного автоматического продолжения используйте модем на черепахе
и четыре загруженных GPS-хоста. Начальное направление указывается явно и должно
совпадать с направлением черепахи:

```text
branchminer new 30 20 3 --gps --heading north
```

Допустимые направления: `north`, `east`, `south`, `west`.
[Как построить GPS](https://tweaked.cc/guide/gps_setup.html).

До каждого перемещения или поворота записывается его намерение, после успеха —
результат. GPS определяет, произошло ли прерванное перемещение. Если исход поворота
неясен, программа проверяет направление коротким выходом в свободную соседнюю
клетку и возвращением обратно, **ничего не копая**. Сам этот проверочный выход
также переживает перезапуск. Для него нужны хотя бы одна свободная горизонтальная
соседняя клетка и топливо; GPS-хосты должны работать.

Если в глубоком карьере вокруг новой клетки ещё сплошная порода, программа
поднимается по открытой колонне на очищенный слой, определяет направление там
и возвращается в ту же клетку. Подъём и спуск также сохраняются и не требуют
выкапывания соседних блоков. Восстановлению всё равно нужны топливо, GPS и свободная
горизонтальная клетка на проверочном слое.

Без GPS прерванное перемещение обычно определяется по расходу топлива на один
блок. Однако у поворота расхода нет. В неоднозначной ситуации программа остановится
с сохранённой базой и заданием. Сверив фактическое положение/направление, подтвердите:

```text
branchminer recover before
branchminer recover after
branchminer resume
```

`before` означает, что записанное незавершённое действие **не совершилось**,
`after` — что оно **совершилось**. Выполняется только одна из этих двух команд.
Не угадывайте и не заправляйте черепаху между неопределённым перемещением и его
сверкой по топливу. У режима GPS нет этой зависимости от топливного счётчика.

Если после аварии сервер откатил мир, координаты могут расходиться с контрольной
записью; программа с GPS остановится для проверки и не объявит новую базу. Полное
восстановление произвольного отката мира не обещается. При обычных паузах,
выгрузке и штатных перезапусках сохраняются база, задание и маршрут.

## Настройки

Опции добавляются после трёх числовых аргументов `new` или радиуса `quarry`:

| Опция | Действие |
|---|---|
| `--gps --heading north` | Проверка положения через GPS и восстановление направления |
| `--no-veins` | Только тоннели, без обхода жил |
| `--no-pave` | Не закрывать отверстия в полу |
| `--bounds -40,40,0,70` | Ограничить рабочую область X и Z |
| `--discard-common` | Выбрасывать обычную породу; по умолчанию она сохраняется |
| `--attack` | Атаковать мешающих существ; по умолчанию программа ждёт |

По умолчанию радиус обхода жил — 6 блоков, предел — 128 блоков на один обход;
сохраняются две контрольные записи с проверкой целостности. При ошибке записи
следующее физическое движение не выполняется. Программа не ломает другие
черепахи, компьютеры, сундуки и известные неразрушаемые блоки на своём пути.

## Проверки

Тесты запускают **реальный `branchminer.lua` в Lua 5.2** с моделью API CC:Tweaked,
мира, топлива, инвентарей, GPS и файловой системы:

```sh
python -m pip install lupa==2.6
python tests/run_tests.py
```

Проверены **40 сценариев**, включая **40 принудительных остановок для тоннелей**
и **438 для карьеров** до и после физического движения или поворота. Проверяются
схема тоннелей и полное выкапывание карьера, неровный бедрок, неизменная база,
паузы, топливо, заполненные сундуки, обход жил, обслуживание, ограничения области,
повреждение контрольной записи, совместимость старых заданий и обновление программы.
Дополнительно проверяются повторные остановки при подъёме, проверочном выходе
и возврате во время GPS-восстановления в карьере.
Это моделирование, а не испытание программы в живом мире Minecraft.
