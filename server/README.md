# Помощник для собственного выделенного сервера

`assist.py` — необязательная служба Python 3.9+ без внешних библиотек. Нужен доступ
администратора к файлам мира, FIFO консоли Minecraft и журналу systemd.
Обычная установка Lua на игровом хостинге продолжает работать без этой службы.

Служба читает запрос только от остановившегося на проверке работника. Через
`execute if block ... if data block ...` она подтверждает ID компьютера,
координаты и направление **живого блока**, затем передаёт ответ программе.
Сохранённый поворот или шаг принимается лишь при совпадении одного из двух
записанных исходов. Ответ связан с ID задания, поколением сохранения и новым
токеном запроса; устаревший ответ не может повернуть или переместить черепаху.
При внешнем переносе, неизвестной позиции или недоступной консоли добыча ждёт
проверки. Помощник не телепортирует черепах, не выдаёт предметы и не меняет блоки.
Для однозначного ответа консоли он записывает только собственную диагностическую
таблицу `branchminer:assist` в command storage, с отдельным токеном каждой проверки.

Раз в две секунды Lua публикует относительную позицию. Помощник переносит
`forceload` на текущий чанк: сначала загружает новый, затем снимает собственный
предыдущий билет. Существующие чужие билеты остаются. Чанк с билетом также
поддерживает тикающих соседей, поэтому следующий переход готовится заранее.
Нужны ресурсы только на текущую область работы, а не на всю будущую шахту.

## Развёртывание

1. Остановить работников через `branchminer pause`, дождаться удаления `run.lock`,
   сохранить полные каталоги компьютеров и установить `branchminer.lua` 1.4.0.
2. Скопировать `assist.py` в `/usr/local/lib/branchminer-assist/assist.py` и unit
   в `/etc/systemd/system/branchminer-assist.service`. В unit проверить путь мира
   и имя службы Minecraft; заранее создать `/var/lib/branchminer-assist`.
3. Записать `/etc/branchminer-assist.json`. Пример структуры:

```json
{
  "computer_root": "/srv/minecraft/WORLD/computercraft/computer",
  "bindings": {
    "1": {
      "job": "1:1234567890",
      "home": [100, 64, 200],
      "heading": 2,
      "seed": [100, 64, 190]
    }
  }
}
```

`home` — подтверждённая **исходная** мировая база, `heading` — её начальное
направление (0 юг, 1 восток, 2 север, 3 запад), `seed` — текущая позиция для
начальной загрузки чанка. Для уже идущего задания нельзя подставлять текущую
позицию вместо базы. До запуска сверить якорь с исходным сундуком и живым блоком.

4. В `.branchminer/server-assist` каждого указанного компьютера записать ровно
   `1` с переводом строки; сохранить владельца файлов Minecraft.
5. Выполнить `systemctl daemon-reload`, `systemctl enable --now branchminer-assist`.
   Затем продолжить прежние задания через `branchminer resume`.

При **новом** задании 1.4.0 черепаха ждёт подтверждения до первого движения.
Помощник проверяет её живую позицию и записывает отдельный якорь нового задания
в `/var/lib/branchminer-assist/anchors.json`. Он не переопределяет базу старого
прерванного задания. Служба связана с перезапусками `minecraft.service`.

Диагностика: `journalctl -u branchminer-assist`, `branchminer status` и
`/var/lib/branchminer-assist/tickets.json`. При остановке службы существующие
работники продолжают обычное копание, но для восстановления прерванного шага
ждут её возвращения. Для полного удаления сначала остановить работников,
убрать `server-assist`, снять только билеты из `tickets.json`, отключить службу;
задания и базы удалять не требуется.
